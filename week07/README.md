## Йерархични структури от данни (Hierarchical data structures)

Йерархичните структури от данни имат главна стойност, която се нарича **корен** (root), от която тръгват разклонения от възли, оформящи йерархична връзка на принципа parent-child. Всеки възел, от който произлизат едно или повече разклонения, се нарича **родител** (parent), а подчинените му възли — **деца** (children). По този начин се създава сложна разклоняваща се структура.

### Наредба на елементите при линейни и йерархични структури

Нека `R` е релация (елементите ѝ са от вида `<x, y>`) и `<x, y> ∈ R` тогава и само тогава, когато `x` е предшественик на `y`. Тогава:

- Множеството от елементите на йерархичните структури, заедно с релацията „предшествие“, образуват **частично наредено множество** — не всеки два елемента могат да бъдат сравнени по критерия „предшествие“.
- Множеството от елементите на линейните структури от данни, заедно с релацията „предшествие“, образуват **линейно наредено множество** — няма несравними елементи по този критерий.

## Дървета

![Двоично дърво](https://i.ibb.co/MZcSHQM/Binary-tree.png)

### Двоични дървета

Ще ги представяме със следната структура:

```cpp
template <typename T>
struct Node
{
    T data;

    Node<T> *left;
    Node<T> *right;
};
```

### N-арни дървета

Ще ги представяме със следната структура:

```cpp
template <typename T>
struct NodeFull
{
    T data;

    std::vector<NodeFull<T> *> children;
};
```

Същото дърво се записва и с **две** връзки вместо вектор: „първо дете“ и „следващ брат“ (left-child right-sibling). Тогава n-арното дърво изглежда като двоично, а списъкът от деца е обикновен едносвързан списък.

```cpp
struct NodeLCRS
{
    int data;

    NodeLCRS *firstChild;
    NodeLCRS *nextSibling;
};
```

### Представяния на дърво

Указателите надолу — от родител към деца — не са единственият начин да се пази дърво. Нека дървото е

```text
            0
          /   \
         1     2
        / \     \
       3   4     5
          / \
         6   7
```

Същото дърво се записва по всеки от следните начини:

| Представяне                       | Записът на дървото по-горе                            | Децата на възел                        | Родителят на възел              | Памет                                      |
| :-------------------------------- | :---------------------------------------------------- | :------------------------------------- | :------------------------------ | :----------------------------------------- |
| указатели надолу                  | `left` и `right`, или `children`                      | O(1) — следваш указателя               | няма — иска търсене от корена   | по един указател на дете                   |
| масив по нива (записът от условията) | `[0,1,2,3,4,null,5,null,null,6,7]`                 | само след построяване                  | само след построяване           | n клетки плюс `null`-овете                 |
| масив по формулата `2i+1` / `2i+2` | `[0,1,2,3,4,_,5,_,_,6,7]`                            | O(1) — клетките `2i+1` и `2i+2`        | O(1) — клетката `(i-1)/2`       | клетка и за всеки липсващ възел, до 2^h    |
| масив от родители                 | `[-1,0,0,1,1,2,4,4]`                                  | иска едно минаване по масива           | O(1) — `parent[i]`              | точно n числа                              |
| списък от ребра                   | `(0,1) (0,2) (1,3) (1,4) (2,5) (4,6) (4,7)`           | O(1) след групиране по родител         | O(1) след групиране по дете     | n-1 двойки                                 |

Третият ред е дърво без нито един указател: ако няма липсващи възли, формулата `2i+1` / `2i+2` е самата структура. Един липсващ възел обаче оставя дупка, а дърво, изродено в списък, стига до индекс 2^(n-1) - 1 — тоест иска масив с 2^(n-1) клетки за n възела. Затова така се пазят само дървета, на които формата е гарантирана.

### Масивът от родители

`parent[i]` е индексът на родителя на възела `i`, а коренът носи `-1`:

```cpp
std::vector<int> parent = {-1, 0, 0, 1, 1, 2, 4, 4};
```

Цялото дърво са n числа — няма указатели, няма `new` и `delete`, а входът се чете с един цикъл. Посоката, която указателите не дават, тук е евтина: пътят до корена, дълбочината на възел, проверката „предшественик ли е `x` на `y`“ и най-ниският общ предшественик са цикли от вида `node = parent[node]`, в които една стъпка нагоре е една индексация.

Платеното е обратната посока. За да се тръгне надолу, децата се събират с едно минаване по масива:

```cpp
std::vector<std::vector<int>> childrenOf(const std::vector<int> &parent)
{
    std::vector<std::vector<int>> children(parent.size());

    for (size_t i = 0; i < parent.size(); i++)
    {
        if (parent[i] != -1)
        {
            children[parent[i]].push_back(i);
        }
    }

    return children;
}
```

Същият масив се среща и извън дърветата: обхождането на граф запомня от кой връх е стигнало до кой и връща точно такъв масив, а структурата за непресичащи се множества (union-find) е гора, пазена само с родители.

### Задача 2. Дърво от масив по нива

Условията по-горе задават дърво като масив по нива: отляво надясно, ниво по ниво, а `null` означава липсващо дете. Първият елемент е коренът; всеки следващ попълва по две клетки — лявото и дясното дете — на поредния вече създаден възел. Децата на `null` не се изброяват, защото `null` не е възел и няма деца.

Напишете функция, която по такъв масив от символни низове построява дървото и връща корена му, както и обратната функция, която по корен връща масива по нива без излишните `null` накрая.

```text
Input:  tokens = ["1","null","2","3"]              Output: [1,null,2,3]
Input:  tokens = ["3","9","20","null","null","15","7"]    Output: [3,9,20,null,null,15,7]
Input:  tokens = ["1","2"]                         Output: [1,2]
Input:  tokens = []                                Output: []
```

**Ограничения:**

- Броят на елементите в масива е в диапазона [0, 10<sup>4</sup>].
- Всеки елемент е или цяло число, или низът `null`.
- Гарантирано е, че масивът описва дърво — всяка двойка клетки принадлежи на вече създаден възел.

За двете функции трябва да важи `levelArray(buildTree(tokens)) == tokens`, когато в `tokens` няма `null` накрая.

### Задача 7. Дърво на израз от инфиксен запис

Дървото на израз е двоично дърво, което представя аритметичен израз. Всеки възел има или нула, или две деца. Листата (възлите без деца) съответстват на операнди (числа), а вътрешните възли (с две деца) — на операторите `+`, `-`, `*` и `/`.

За всеки вътрешен възел с оператор `o` инфиксният израз, който представя, е `(A o B)`, където `A` е изразът на лявото поддърво, а `B` — на дясното.

Даден е низ `s` — инфиксен израз, съдържащ операнди, изброените оператори и скоби. Върнете дървото на израза, чието inorder обхождане възстановява `s`.

Приоритетът на операциите важи: първо се пресмятат изразите в скоби, а умножението и делението — преди събирането и изваждането.

![Дърво на израз](https://assets.leetcode.com/uploads/2020/09/20/sample_1_1978.png)

```text
Input:  s = "2-3/(5*2)+1"
Output: [+,-,1,2,/,null,null,null,null,3,*,null,null,5,2]

Input:  s = "3*4-2*5"
Output: [-,*,*,3,4,2,5]

Input:  s = "1+2+3+4+5"
Output: [+,+,5,+,4,null,null,+,3,null,null,1,2]
```

**Ограничения:**

- 1 <= s.length <= 10<sup>5</sup>
- `s` се състои от цифри и символите `+`, `-`, `*`, `/`, `(` и `)`.
- Операндите в `s` са точно една цифра.
- Гарантирано е, че `s` е валиден израз.

### Задача 8. Коледни подаръци

Жоро е изпълнителен директор на технологичния гигант V&GCorp. Тъй като наближават коледните празници, се налага да купи подаръци на всички свои подчинени — преки или косвени (подчинени на подчинени) — така, че да няма много причини да мрънкат. Проблемът е, че ако той подари на даден служител подарък, а прекият му началник не му подари, то служителят ще мрънка на прекия си началник.

Вашата задача е по дадената йерархична структура на компанията да прецените кой началник колко подаръка ще купи, ако знаете, че всеки началник ще купи подарък на всичките си служители.

Йерархичната структура е дърво, индексирано от 0 до N-1, като Жоро е в корена с индекс 0 и всеки връх съответства на човек от компанията. Ако връх с индекс `x` е родител на връх с индекс `y`, това значи, че човекът, съответстващ на върха `x`, е пряк началник на човека, съответстващ на върха `y`.

Въвежда се броят `N` на служителите, а след това на всеки от следващите `N-1` реда — по две числа `x` и `y`, означаващи, че върхът с индекс `x` е родител на върха с индекс `y`.

Извеждат се `N` числа, разделени с празно място, като `i`-тото число отговаря на броя подаръци, които трябва да купи човекът, съответстващ на върха с индекс `i`.

```text
Input:  9
        0 1
        0 2
        1 3
        1 4
        1 5
        1 6
        4 7
        7 8

Output: 8 6 0 0 2 0 0 1 0
```

### Задача 9. Най-нисък общ предшественик по масив от родители

Дърво с `N` възела, индексирани от 0 до N-1, е зададено с масив от родители: `parent[i]` е индексът на родителя на възела `i`, а коренът носи `-1`. Указатели няма — масивът е цялото дърво.

Напишете две функции:

- `pathToRoot(parent, node)` — възлите по пътя от `node` до корена, заедно с двата края;
- `lowestCommonAncestor(parent, u, v)` — най-ниският общ предшественик на `u` и `v`, тоест най-дълбокият възел, който е предшественик и на двата. Всеки възел е предшественик на себе си.

```text
parent = [-1, 0, 0, 1, 1, 2, 4, 4]

            0
          /   \
         1     2
        / \     \
       3   4     5
          / \
         6   7

pathToRoot(parent, 7)                 ->  [7, 4, 1, 0]
pathToRoot(parent, 0)                 ->  [0]
lowestCommonAncestor(parent, 3, 7)    ->  1
lowestCommonAncestor(parent, 6, 7)    ->  4
lowestCommonAncestor(parent, 3, 5)    ->  0
lowestCommonAncestor(parent, 4, 7)    ->  4
lowestCommonAncestor(parent, 5, 5)    ->  5
```

**Ограничения:**

- 1 <= N <= 10<sup>5</sup>
- Точно един елемент на `parent` е `-1`; останалите са валидни индекси.
- Гарантирано е, че масивът описва дърво — няма цикли.
- Височината не е ограничена: дървото може да е изродено в списък.

`lowestCommonAncestor` да работи за O(h) време и O(1) допълнителна памет, без да построява дърво с указатели. Двата пътя до корена са два списъка, които накрая се сливат — търсеният възел е първият им общ елемент.
