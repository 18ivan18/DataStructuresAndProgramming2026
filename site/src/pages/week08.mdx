## Задачата, която решаваме

Искаме структура, която пази двойки ключ-стойност и може три неща: да **намери** стойността по
ключ, да **вмъкне** нова двойка и да **изтрие** двойка. Досегашните структури правят едното за
сметка на другото:

| Структура            | намиране     | вмъкване   | подредено изброяване |
| :------------------- | :----------- | :--------- | :------------------- |
| несортиран масив     | O(n)         | O(1)       | трябва сортиране     |
| сортиран масив       | O(log n) с двоично търсене | O(n) — всичко след мястото се мести | наготово |
| свързан списък       | O(n)         | O(1)       | трябва сортиране     |
| **двоично наредено дърво** | **O(h)** | **O(h)**  | **наготово, inorder** |

Сортираният масив вече може да търси бързо; проблемът му е, че наредбата се пази чрез **позиции**, а
преместването на позиция струва. Дървото пази същата наредба чрез **указатели** — и точно затова
вмъкването не мести нищо, а само закача един нов възел.

## Наредбата

Двоично наредено дърво (binary search tree) е двоично дърво, в което за **всеки** възел:

- всички ключове в лявото му поддърво са по-малки от неговия;
- всички ключове в дясното му поддърво са по-големи от неговия;
- лявото и дясното поддърво също са двоично наредени дървета.

```cpp
template <typename Key, typename Value>
struct Node
{
    Key key;
    Value value;

    Node *left;
    Node *right;
};
```

Наредбата е по ключове: при търсене подаваме ключ и получаваме стойност. Стойността не участва в
сравненията — може да се повтаря, ключът не може.

Условието е за **цялото поддърво**, не за прякото дете. Това е най-честата грешка в задача 1: дърво,
в което всеки възел е наред спрямо родителя си, но не спрямо дядо си, не е BST. Затова проверката
носи надолу **интервал**: всеки възел трябва да е в прозореца, който му оставят всички негови
предци.

Едно изречение следва от наредбата и върши работа почти навсякъде:

> **Inorder обхождането на BST дава ключовете в растящ ред.**

Оттам задача 2 (k-тият най-малък е k-тият по ред), задача 8 (итераторът е спряно по средата inorder
обхождане) и най-късата проверка за валидност (inorder трябва да излезе строго растящо).

## Формата зависи от реда на вмъкване

Едни и същи ключове дават различни дървета според реда, в който са вмъкнати — а формата е цялата
сложност. Пробвай сортиран ред:

<BstShape client:visible />

Дърво с n възела е високо между ⌈log₂(n + 1)⌉ и n. Горната граница не е теоретичен страх: сортиран
вход (а той е най-обичайният — данни, подредени по време или по номер) изражда дървото в свързан
списък с указател повече. Затова сложността на BST се пише **O(h)**, а където трябва гаранция, се
използва балансирано дърво — седмица 10.

## Търсене, вмъкване, триене

Търсенето е единственото, което трябва да се разбере: всичко останало е то плюс една стъпка.

```cpp
TreeNode *searchBST(TreeNode *root, int val)
{
    while (root && root->val != val)
    {
        root = root->val < val ? root->right : root->left;
    }
    return root;
}
```

Всяко сравнение изхвърля **цяло поддърво**. Цикълът свършва по един от два начина: намерен възел или
`nullptr` — а `nullptr` е точно мястото, където стойността би трябвало да е, ако я имаше.

**Вмъкването** е търсене, което не е намерило: там, където търсенето стига до `nullptr`, се закача
новият възел. Новият ключ винаги става листо, нищо съществуващо не се мести.

```cpp
TreeNode *insertIntoBST(TreeNode *root, int val)
{
    if (!root)
    {
        return new TreeNode(val);
    }

    if (root->val > val)
    {
        root->left = insertIntoBST(root->left, val);
    }
    else
    {
        root->right = insertIntoBST(root->right, val);
    }

    return root;
}
```

Функцията връща указател и резултатът се присвоява обратно на `root->left` или `root->right`. При
непразно дърво присвояването връща същия указател — излишно изглеждащо, но то е, което прави
единствения случай с нов корен (празното дърво) да се пише без отделна ветка.

**Триенето** е трите случая, които трябва да се знаят наизуст:

| Случай                | Какво става                                                      |
| :-------------------- | :--------------------------------------------------------------- |
| листо                 | родителят получава `nullptr` на негово място                      |
| едно дете             | детето заема мястото му заедно с цялото си поддърво               |
| две деца              | възелът се заменя със следващия по inorder ред — най-малкия в дясното поддърво |

Първите два случая се пишат с един ред (`return x->left` или `return x->right`: при листо това е
`nullptr`). Третият е интересният: нито едно от двете деца не може просто да се вдигне, затова се
взема **наследникът** — най-малкият ключ отдясно. Той е по-голям от всичко отляво и по-малък от
всичко останало отдясно, значи наредбата се запазва. И още: той няма ляво дете, иначе не би бил
най-малкият — затова изваждането му е лесно.

Може да се вземе и предшественикът (най-големият ключ отляво) — също вярно. Симетричен избор.

## Сериализация без нито един `null`

При произволно двоично дърво preorder обхождането не стига, за да се възстанови дървото: трябват и
`null`-овете, иначе не се познава кое е ляво и кое дясно поддърво. При **наредено** дърво стигат само
ключовете:

```text
5 3 2 4 8 7
```

Първото число е коренът. Всичко след него, което е **по-малко** от 5, е лявото поддърво; първото
по-голямо (8) започва дясното. Търсенето на тази граница е `std::upper_bound` в решението на задача
3. Наредбата играе ролята, която при обикновено дърво играят `null`-овете.

## Итератор

Задачата на итератора е да даде стойностите в растящ ред, без да строи масив. Лесният вариант —
inorder в `std::vector` в конструктора — е O(n) памет и върши работа, но не върши работата на
`std::map`: нужен е итератор, който може да спре по средата и да продължи.

Трикът е да се държи **само левият ръб** в стек:

```cpp
void partialInorder(TreeNode *root)
{
    while (root)
    {
        s.push(root);
        root = root->left;
    }
}
```

Конструкторът слага левия ръб от корена; на върха стои най-малкият ключ. `next()` вади върха и слага
левия ръб на **дясното** му поддърво. Стекът пази точно възлите, които са „отворени, но още не
върнати“: O(h) памет вместо O(n), а едно `next()` може да е O(h), но n извиквания правят общо O(n) —
амортизирано O(1).

Назад така не става: дърво не се обхожда наобратно без родителски указатели. Затова задача 9 пази
вече върнатите стойности и `prev()` само мести указател — цената е памет O(n).

## Сложност

| Операция                  | Сложност   | В най-лошия случай |
| :------------------------ | :--------- | :----------------- |
| търсене, вмъкване, триене | O(h)       | O(n) при изродено дърво |
| k-тият най-малък          | O(h + k)   | O(n)               |
| минимум, максимум         | O(h)       | O(n)               |
| подредено изброяване      | O(n)       | O(n)               |
| памет на итератора        | O(h)       | O(n)               |

Нищо от горното не зависи от броя на възлите сам по себе си — зависи само от височината. С n възела
h е между ⌈log₂(n + 1)⌉ и n, и кое от двете ще се случи, решава редът на вмъкване, а не кодът.

# Задачи

### Задача 1. Валидиране на двоично наредено дърво

По подаден корен на двоично дърво определете дали дървото е двоично наредено дърво за търсене
(binary search tree, BST).

Трябва да са изпълнени следните правила:

- Лявото поддърво съдържа само върхове със стойности, по-малки от корена.
- Дясното поддърво съдържа само върхове със стойности, по-големи от корена.
- Лявото и дясното поддърво също трябва да са валидни двоични наредени дървета за търсене.

![Валидно BST](https://assets.leetcode.com/uploads/2020/12/01/tree1.jpg)

```text
Input:  root = [2,1,3]               Output: true
Input:  root = [5,1,4,null,null,3,6] Output: false
```

Във втория пример стойността на корена е 5, но дясното му дете е 4.

Проверката носи надолу интервала, който предците оставят на възела: наляво горната граница става

Пусни `5 4 6 null null 3 7`: 3 е наред спрямо родителя си 6, но е в дясното поддърво на 5, където
всичко трябва да е по-голямо от 5. Точно това пропуска проверката „всяко дете спрямо родителя си“ —
най-честото грешно решение на тази задача.

Пробвай и `2 2`: границите са **строги**, затова равни ключове не минават. В BST с двойки
ключ-стойност повтарящ се ключ няма смисъл — `put` със съществуващ ключ сменя стойността.

Другият верен начин е inorder обхождане с проверка, че всяка стойност е строго по-голяма от
предишната. Същата сложност, O(n) време и O(h) памет; дори спира на първото нарушение, стига да не
се трупа масив.

### Задача 2. K-ти най-малък елемент в BST

По даден корен на двоично наредено дърво и цяло число `k` върнете `k`-тия най-малък елемент (броим

![K-ти най-малък](https://assets.leetcode.com/uploads/2021/01/28/kthtree1.jpg)

```text
Input:  root = [3,1,4,null,2], k = 1             Output: 1
Input:  root = [5,3,6,2,4,null,null,1], k = 3    Output: 3
```

**Ограничения:**

- Броят на възлите е `n`.
- 1 &lt;= k &lt;= n &lt;= 10<sup>4</sup>
- 0 &lt;= Node.val &lt;= 10<sup>4</sup>

`size(Node *)` в класа `BST`.

### Задача 3. Сериализация и десериализация на BST

Сериализацията на структура от данни или обект представлява представянето му като поредица от битове
(или символи), които да се пазят в буфер или да се предават по мрежата с цел предаване на друга
програма и пресъздаване на съответната структура.

Нашата цел е да направим алгоритъм, който сериализира двоично наредено дърво, като го превърне в
символен низ. Трябва също да можем да десериализираме дърво — по подадения низ да построим дървото
обратно.

```text
Input:  root = [2,1,3]    Output: [2,1,3]
Input:  root = []         Output: []
```

**Ограничения:**

- Броят на възлите е в диапазона [0, 10<sup>4</sup>].
- 0 &lt;= Node.val &lt;= 10<sup>4</sup>
- Гарантирано е, че подаденото дърво е двоично наредено дърво.

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

Първата половина на трасето записва preorder, втората го чете обратно. Лентата показва отрязъка, с
който работи текущото извикване, а отбелязаната клетка е коренът му.

<BstTaskTrace task="serialize" client:visible />

Защо preorder, а не inorder? Inorder на BST е сортираният масив — от него се възстановява множеството
от ключове, но не и формата: всички дървета с тези ключове имат едно и също inorder. Preorder носи
кой е корен на всяко поддърво, а наредбата казва къде свършва лявото.

Разделянето с `upper_bound` е O(размера на отрязъка), значи O(n) на ниво и O(n · h) общо — при
изродено дърво O(n²). С граници, подадени като параметри (минимум и максимум на отрязъка), всеки
елемент се пипа по веднъж и десериализацията става O(n).

За **произволно** двоично дърво същият номер не работи: там трябват и `null`-овете, тоест записът по
нива от задача 2 на седмица 7 или preorder с маркери за липсващи деца.

</details>

### Задача 4. Сортиран списък към балансирано BST

По подадено начало на свързан списък, чиито елементи са възходящо подредени, постройте балансирано
двоично наредено дърво за търсене.

![Списък към BST](https://assets.leetcode.com/uploads/2020/08/17/linked.jpg)

```text
Input:  head = [-10,-3,0,5,9]
Output: [0,-3,9,-10,null,5]

Input:  head = []
Output: []
```

Възможни са няколко верни отговора — всяко балансирано дърво с тези елементи се приема.

**Ограничения:**

- Броят на възлите е в диапазона [0, 2 * 10<sup>5</sup>].
- -10<sup>5</sup> &lt;= Node.val &lt;= 10<sup>5</sup>

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

Сортираният вход вече е inorder редът, значи остава само да се избере коренът. Избира се средата: при
нея двете половини са еднакви по брой и височината е най-малката възможна. После същото за всяка
половина.

<BstTaskTrace task="sorted" client:visible />

Средата се намира с двата указателя от седмица 6 — бавният тръгва на една стъпка, бързият на две,
затова бавният стига средата точно когато бързият стигне края. Броят на елементите не се пресмята
предварително.

`temp->next = nullptr` е редът, който разрязва списъка: без него рекурсията за лявата половина ще
продължи през средата и нататък и няма да спре. Изродените случаи (празен списък, един елемент) са
първите два `if`-а.

Сложността е O(n log n): всяко ниво на рекурсията минава през своите елементи, за да намери средата,
а нивата са log n. С масив вместо списък е O(n), защото средата е `(lo + hi) / 2` без обхождане.
Същата конструкция е и конструкторът на класа `BST` — той приема сортиран масив точно затова.

</details>

### Задача 5. Търсене в BST

По даден корен на двоично наредено дърво и стойност на елемент проверете дали елементът се съдържа в
дървото. Измислете подходящо решение за случая, в който елементът не се съдържа в дървото.

![Търсене в BST](https://assets.leetcode.com/uploads/2021/01/12/tree1.jpg)

```text
Input:  root = [4,2,7,1,3], val = 2    Output: [2,1,3]
Input:  root = [4,2,7,1,3], val = 5    Output: []
```

**Ограничения:**

- Броят на възлите е в диапазона [1, 5000].
- 1 &lt;= Node.val &lt;= 10<sup>7</sup>
- 1 &lt;= val &lt;= 10<sup>7</sup>
- `root` е двоично наредено дърво.

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

<BstTaskTrace task="search" client:visible />

Отговорът на „какво връщаме, като го няма“ е `nullptr`, не изключение и не флаг: липсващият ключ е
обичаен резултат, а празното поддърво вече си има представяне. Функцията връща **указател към възел**,
тоест цялото поддърво с този корен — затова примерът в условието показва `[2,1,3]`, а не само `2`.

Класът `BST` връща не указател, а **итератор**, и сравнението с `end()` казва има ли го. Същата идея
като `std::map::find`: един и същ тип за „намерено“ и за „няма такова“.

Пусни `1 null 2 null 3 null 4` и потърси 4: четири сравнения за четири възела. Търсенето не е
O(log n) — то е O(h), а h е такова, каквото редът на вмъкване го е направил.

Рекурсивният вариант изглежда по-симпатично, но итеративният не заема рамки и е естественият избор
тук: рекурсията е опашкова, тоест не носи нищо със себе си надолу.

</details>

### Задача 6. Вмъкване в BST

По даден корен на двоично наредено дърво и число поставете числото в дървото и върнете корена след
успешното поставяне. Предварително знаем, че даденото число не се съдържа вече в дървото.

Забележете, че може да има няколко валидни начина за поставяне на елемента — всеки от тях е верен
отговор.

![Вмъкване в BST](https://assets.leetcode.com/uploads/2020/10/05/insertbst.jpg)

```text
Input:  root = [4,2,7,1,3], val = 5               Output: [4,2,7,1,3,5]
Input:  root = [40,20,60,10,30,50,70], val = 25   Output: [40,20,60,10,30,50,70,null,null,25]
```

**Ограничения:**

- Броят на възлите е в диапазона [0, 10<sup>4</sup>].
- -10<sup>8</sup> &lt;= Node.val &lt;= 10<sup>8</sup>
- Всички стойности в дървото са различни.
- -10<sup>8</sup> &lt;= val &lt;= 10<sup>8</sup>
- Гарантирано е, че `val` не се съдържа в дървото.

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

<BstTaskTrace task="insert" client:visible />

Пътят е същият, по който би минало търсенето на `val`; новият възел застава там, където търсенето би
върнало `nullptr`. Затова вмъкването е O(h) и не мести нито един съществуващ възел — сравни със
сортирания масив, където същата операция мести средно половината елементи.

Трите варианта в `solutions/6.cpp` правят едно и също. Рекурсивният разчита на присвояването
`root->left = insertIntoBST(root->left, val)`: при непразно поддърво то връща същия указател, а при
празно — новия възел, и така родителят се закача без отделна проверка. Итеративният вариант пази
`preNode`, защото, като стигне `nullptr`, трябва да знае чие дете да стане.

Вмъкни няколко стойности в растящ ред и гледай какво става с височината. Балансираните дървета от
седмица 10 добавят точно тук една стъпка: след закачането поправят формата.

</details>

### Задача 7. Триене на възел в BST

По даден корен на двоично наредено дърво и ключ изтрийте върха с подадения ключ. Върнете корена на
дървото като резултат.

Изтриването може да се раздели на две стъпки:

- Намираме елемента за триене.
- Ако го намерим, го изтриваме.

![Триене на възел](https://assets.leetcode.com/uploads/2020/09/04/del_node_1.jpg)

```text
Input:  root = [5,3,6,2,4,null,7], key = 3    Output: [5,4,6,2,null,null,7]
Input:  root = [5,3,6,2,4,null,7], key = 0    Output: [5,3,6,2,4,null,7]
Input:  root = [], key = 0                    Output: []
```

За първия пример `[5,2,6,null,4,null,7]` също е верен отговор. Във втория пример дървото не съдържа
връх със стойност 0.

![Друг верен отговор](https://assets.leetcode.com/uploads/2020/09/04/del_node_supp.jpg)

**Ограничения:**

- Броят на възлите е в диапазона [0, 10<sup>4</sup>].
- -10<sup>5</sup> &lt;= Node.val &lt;= 10<sup>5</sup>
- Всеки връх има уникална стойност.
- -10<sup>5</sup> &lt;= key &lt;= 10<sup>5</sup>

Може ли да решите задачата със сложност O(височина на дървото)?

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

<BstTaskTrace task="delete" client:visible />

Пробвай и трите случая върху `5 3 6 2 4 null 7`: ключ 2 е листо, ключ 6 има едно дете, ключ 5 (или 3)
има две. Третият случай е единственият, в който се мести възел — наследникът, тоест най-малкият в
дясното поддърво. `deleteMin` го изважда оттам, а след това той получава старото ляво поддърво и
остатъка от дясното.

Защо точно наследникът? Защото е следващият по inorder ред: той е по-голям от всичко отляво и
по-малък от всичко останало отдясно, значи наредбата остава. Най-големият отляво върши същата работа
— оттам идват двата верни отговора в условието.

Сложността е O(h): един път надолу до възела и още един до най-малкия отдясно. Важното е, че
дълбочината не се удвоява — двата пътя са един след друг, не един в друг.

Изтрий ключ, който не е в дървото: връща се същият корен, без промяна. Това не е грешка и не
изисква съобщение — както при търсенето.

</details>

### Задача 8. Итератор на BST

Да се реализира класът `BSTIterator`, който представлява итератор по inorder обхождането на двоично
наредено дърво:

- `BSTIterator(TreeNode *root)` — инициализира обекта. Коренът на дървото се подава в конструктора.
  Указателят се инициализира на несъществуващо число, по-малко от всеки елемент в дървото.
- `bool hasNext()` — връща `true`, ако в обхождането има число вдясно от указателя.
- `int next()` — премества указателя надясно и връща числото, на което сочи.

Тъй като указателят започва преди най-малкия елемент, първото извикване на `next()` връща най-малкия
елемент в дървото.

Можем да приемем, че извикванията на `next()` винаги са валидни — когато се извика, винаги има
следващо число в обхождането.

![Дърво за итератора](https://assets.leetcode.com/uploads/2018/12/25/bst-tree.png)

```cpp
class BSTIterator
{
public:
    BSTIterator(TreeNode *root);

    int next();
    bool hasNext();
};
```

```text
BSTIterator iterator(root);   // дървото е [7,3,15,null,null,9,20]
iterator.next();              // 3
iterator.next();              // 7
iterator.hasNext();           // true
iterator.next();              // 9
iterator.hasNext();           // true
iterator.next();              // 15
iterator.hasNext();           // true
iterator.next();              // 20
iterator.hasNext();           // false
```

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

<BstTaskTrace task="iterator" client:visible />

Това е итеративното inorder от седмица 7, разглобено на части: вътрешният цикъл става конструктор и
край на `next()`, а стекът — поле на класа. Състоянието на обхождането вече е обект и може да се
остави и да се вземе отново.

Стекът пази само левия ръб, затова паметта е O(h), а не O(n). Едно `next()` може да е O(h) (когато
слиза по дълъг ляв ръб), но всеки възел влиза и излиза от стека по веднъж за цялото обхождане, значи
n извиквания са общо O(n) — амортизирано O(1) за извикване.

Вариантът с предварително пресметнат `std::vector` (`BSTIteratorPrecomputed`) е по-кратък и също
минава тестовете, но плаща O(n) памет и O(n) в конструктора. Разликата се вижда, когато дървото е
голямо, а трябват първите няколко стойности — или когато дървото се променя, докато го обхождаш.

</details>

### Задача 9. Итератор на BST в двете посоки

Да се реализира класът `BSTIterator`, който освен напред може да се движи и назад по inorder
обхождането:

- `BSTIterator(TreeNode *root)` — инициализира обекта, както в предишната задача.
- `bool hasNext()` — има ли число вдясно от указателя.
- `int next()` — премества указателя надясно и връща числото, на което сочи.
- `bool hasPrev()` — има ли число вляво от указателя.
- `int prev()` — премества указателя наляво и връща числото, на което сочи.

Можем да приемем, че извикванията на `next()` и `prev()` винаги са валидни.

За дървото `[7,3,15,null,null,9,20]` обхождането е `3, 7, 9, 15, 20`. Текущият елемент е отбележен в
скоби:

| Операция    | Резултат | Състояние         |
| :---------- | :------- | :---------------- |
| `next()`    | 3        | **[3]** 7 9 15 20 |
| `next()`    | 7        | 3 **[7]** 9 15 20 |
| `prev()`    | 3        | **[3]** 7 9 15 20 |
| `next()`    | 7        | 3 **[7]** 9 15 20 |
| `hasNext()` | true     | 3 **[7]** 9 15 20 |
| `next()`    | 9        | 3 7 **[9]** 15 20 |
| `next()`    | 15       | 3 7 9 **[15]** 20 |
| `next()`    | 20       | 3 7 9 15 **[20]** |
| `hasNext()` | false    | 3 7 9 15 **[20]** |
| `hasPrev()` | true     | 3 7 9 15 **[20]** |
| `prev()`    | 15       | 3 7 9 **[15]** 20 |
| `prev()`    | 9        | 3 7 **[9]** 15 20 |

Може ли задачата да се реши, без предварително да се пресмятат стойностите на дървото?

<details class="spoiler">
<summary>Спойлер: решението, стъпка по стъпка</summary>

<BstTaskTrace task="iterator2" client:visible />

Може — и точно това прави `solutions/9.cpp`. Стекът остава същият, но до него стои `seen`: вече
върнатите стойности, и указател `i` в тях. `next()` гледа първо дали `i` не е стигнал края на `seen`
— ако не е, стойността се чете оттам и дървото не се пипа; само когато `i` е на края, от стека се
вади нов възел. `prev()` е винаги само `seen[--i]`.

Затова конструкторът пак е O(h): нищо не се пресмята предварително, `seen` се пълни лениво, по една
стойност на всяко ново `next()`. Паметта расте до O(n) само ако наистина обходиш цялото дърво.

Без родителски указатели назад не става: от възел се стига до децата му, не до предшественика му.
Ако възелът пази и `parent`, тогава и `prev()` се смята за O(h) без `seen` — с цената на един
указател в **всеки** възел и грижата да се поддържа при вмъкване и триене.

</details>

# Клас BST

За следващите задачи се иска да се създаде клас `BST`, който ще представлява двоично наредено дърво.

Нашето дърво ще пази двойки ключ-стойност. Нека ключът и стойността бъдат генерични параметри.
Наредбата ще бъде по ключове — при търсене търсим по ключ и намираме стойност.

1. Конструктор, който приема като аргумент сортиран масив от двойки ключ-стойност.
2. Метод `prettyPrint()`, който извежда дървото на екрана по подходящ начин.
3. Метод `contains(T key)`, който проверява дали ключът `key` се съдържа в дървото.
4. Метод `height()`, който намира височината на дървото.
5. Метод `get(T key)`, който по даден ключ връща стойността, която му отговаря.
6. Метод `put(T key, V value)`, който поставя наредената двойка `key`-`value` на подходящото място в
   дървото.
7. Метод `delete(T key)`, който трие двойката ключ-стойност от дървото.
8. Метод `serialize(std::ostream &out)` за сериализация на дървото в Scheme формат.
9. Предикат `isBST()` за проверка.

Всеки от тези методи е една от задачите по-горе: конструкторът е задача 4, `contains` и `get` —
задача 5, `put` — задача 6, `delete` — задача 7, `isBST` — задача 1, а итераторът — задача 8.

Сериализацията в Scheme формат изглежда така:

- Празното дърво се представя като `()`.
- Нека е дадено дървото `t` с корен `x:y`, ляво поддърво `tL` и дясно поддърво `tR`. Ако `sL` е
  представянето в Scheme формат на `tL`, а `sR` — на `tR`, то низът `(x:y sL sR)` е представянето на
  дървото `t`.

Дървото от картинката в [README](https://github.com/18ivan18/DataStructuresAndProgramming2026/tree/main/week08#readme)
се представя като:

```text
(10:Plovdiv (20:Pleven (25:StaraZagora () ()) (15:Silistra () ())) (5:Burgas () ()))
```

Този запис е preorder обхождане със скоби — пълната форма на задача 3, в която `()` са запазените
`null`-ове. Затова от него дървото се възстановява и когато **не** е наредено.

Реализация: [`BST.h`](https://github.com/18ivan18/DataStructuresAndProgramming2026/tree/main/week08/implementation/BST/BST.h)
